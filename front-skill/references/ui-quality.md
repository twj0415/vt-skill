# UI 质量规范

## 基础要求

前端实现不只要求功能可用，也要保证界面清晰、交互稳定、状态符合实际场景。

## 状态完整性

按组件实际交互考虑相关状态，不要求简单组件补完整状态矩阵。

常见状态包括：

- 默认状态
- loading
- hover
- focus
- active
- disabled
- error
- empty
- success
- selected

简单静态展示组件可以只处理必要状态；表单、列表、弹窗、异步请求区域需要更完整。

## 可访问性

- 可点击元素要有明确交互反馈。
- 表单控件要有关联 label 或可理解的占位说明。
- 键盘可操作的组件不要破坏 focus。
- 颜色不能作为唯一信息来源。
- 文本对比度要足够。

## 响应式

- 按项目已支持的端和断点考虑响应式，不默认扩大到所有端。
- 不让内容在目标屏幕尺寸下溢出。
- 表格、卡片、弹窗、导航在项目支持的窄屏场景下要可用。

## 视觉一致性

- 间距、圆角、阴影、字体、颜色遵循项目现有设计体系。
- 不混用多套风格。
- 不使用泛滥的渐变、阴影和特效。

## 组件库

如果项目使用组件库，优先遵循组件库模式，不重复造基础组件。简单局部展示不必抽成通用基础组件。自定义样式不要破坏组件库交互和可访问性。
